# 后端接口性能测试与排查方案

> 适用场景:接口响应速度不稳定(有时快有时慢),需要系统化测试、定位并形成可复现的报告。

## 1. 测试目标与指标定义

| 指标 | 含义 | 参考阈值(按业务调整) |
|---|---|---|
| AVG | 平均响应时间 | < 200ms |
| P95 | 95% 请求快于该值 | < 500ms |
| P99 | 99% 请求快于该值 | < 1000ms |
| QPS/TPS | 每秒处理请求数 | 按容量规划定 |
| 错误率 | 非 2xx / 超时占比 | < 0.1% |

**核心原则:不看平均值,看 P95 / P99。**
平均 50ms 但 P99 = 3s,就是典型的"有时快有时慢"——说明存在慢请求长尾(慢 SQL、GC 停顿、锁竞争、缓存失效、连接池耗尽等)。

## 2. 环境与数据准备

压测结果可信的前提:

- [ ] 使用**独立测试环境**,避免影响生产;若压生产,选低峰期并用流量影子/只读接口
- [ ] 数据量与生产同量级(10 条数据和 100 万数据的 SQL 表现完全不同)
- [ ] 压测机与服务器网络稳定(同一内网优先),排除带宽干扰
- [ ] 记录基线:服务器 CPU / 内存 / 数据库连接池大小的当前配置
- [ ] 每轮压测参数固定(并发数、时长、数据集),保证结果可对比

## 3. 测试流程(三层)

```
第一层:单请求冒烟测试(定位是网络慢还是服务端慢)
   ↓
第二层:低并发采样监测(抓"偶尔慢"的现场,间歇性问题专项)
   ↓
第三层:压力测试(测容量上限与长尾表现)
```

### 3.1 第一层:冒烟测试

使用 `smoke.sh`(见本目录),对单个请求输出 DNS / TCP / TLS / 首字节 / 总耗时。

**结果判读:**

| 现象 | 结论 |
|---|---|
| DNS 或 connect 耗时高 | 网络 / DNS 问题,与服务端无关 |
| starttransfer - connect 高 | 服务端处理慢 → 进入第二、三层 |
| total - starttransfer 高 | 响应体过大 / 带宽不足,考虑 gzip、精简字段 |

### 3.2 第二层:低并发采样监测(间歇性慢专项)

间歇性问题单次请求难以复现,策略是:**长时间低频采样 + 记录每次耗时,事后分析长尾**。

使用 `monitor.sh`(见本目录):

- 以固定间隔(如 2s)持续请求接口,记录时间戳 + 耗时
- 超过阈值(默认 500ms)的请求单独记录到 `slow-requests.log`,并附上当时的服务端信息(若有 APM trace-id 响应头则一并记录)
- 跑 30 分钟~数小时后,用 `analyze.awk` 统计 P50 / P90 / P95 / P99 / MAX,并查看慢请求的时间分布(是否周期性出现 → 定时任务 / 缓存过期 / 日志轮转;是否随机 → GC / 锁 / 连接池)

**慢请求时间分布分析要点:**

- 周期性出现 → 排查定时任务、缓存批量过期、日志切割、DB 备份
- 随机出现 → 排查慢 SQL(无索引查询偶发命中)、GC 停顿、连接池偶发耗尽
- 高并发时段出现 → 排查资源竞争、限流、下游服务容量

### 3.3 第三层:压力测试

使用 k6(`k6-load.js`,见本目录),推荐阶梯加压模型:

| 阶段 | 并发 | 时长 | 目的 |
|---|---|---|---|
| 预热 | 1~5 | 1min | 建立连接、预热缓存/JIT |
| 阶梯 1 | 20 | 3min | 日常负载水平 |
| 阶梯 2 | 50 | 3min | 峰值水平 |
| 阶梯 3 | 100 | 3min | 超出预期,找拐点 |
| 阶梯 4 | 200 | 3min | 容量极限,观察错误率 |

**观察拐点:** 随并发上升,QPS 不再增长且延迟陡增的并发数即为容量拐点。生产容量应控制在拐点的 70% 以内。

**同时观察服务端资源**(压测时另开终端或接监控):

```bash
# CPU / 内存 / 负载
top -o cpu
# 或安装 pidstat(可观察单进程, -u CPU  -r 内存  -d IO)
pidstat -u -r -p <pid> 2
```

- CPU 打满 → 计算瓶颈(序列化、加解密、正则回溯)
- CPU 不高但延迟高 → IO 等待 / 锁 / 连接池 / 下游依赖
- 内存持续上涨 → 内存泄漏,可能触发 Full GC 导致间歇性停顿

## 4. 服务端排查清单(压测确认慢在服务端后)

按链路顺序逐项排查:

### 4.1 日志打点
在入口/出口记录每请求耗时,拆分:`中间件 + 业务逻辑 + DB + 缓存 + 下游 RPC + 序列化`

### 4.2 数据库(最高频原因)
- 开启慢查询日志:MySQL `long_query_time = 0.1`;PostgreSQL 用 `pg_stat_statements`
- `EXPLAIN` 确认索引命中,排查全表扫描
- 排查 N+1 查询(ORM 常见,日志里同一请求出现大量相似 SQL)
- 确认连接池大小是否够(压测时监控 `Threads_waiting` / 活跃连接数)

### 4.3 链路追踪(APM)
- Jaeger / SkyWalking / Zipkin / Datadog
- 看单次慢请求内部每一跳的耗时,直接定位到具体下游或 SQL

### 4.4 语言级 Profiling
| 技术栈 | 工具 |
|---|---|
| Go | pprof + flame graph |
| Java | Arthas `trace`(方法级耗时)、async-profiler |
| Node.js | clinic.js、`--prof` |
| Python | py-spy |

### 4.5 常见间歇性慢的根因对照表

| 现象 | 可能原因 |
|---|---|
| 周期性变慢(如每分钟/每小时) | 定时任务、缓存批量过期、日志轮转、DB 备份 |
| 随机偶发慢 | 慢 SQL 偶发、GC 停顿、连接池偶发耗尽、TCP 重传 |
| 高峰期慢 | 容量不足、下游限流、锁竞争 |
| 首次慢后续快 | 缓存未命中 / 冷启动 / JIT 未预热(可接受,可加预热) |
| 固定比例请求慢 | 某类参数触发的数据倾斜(如大用户的查询范围) |

## 6. 持续保障(可选,防退化)

- **CI 性能门禁**:在流水线中跑轻量压测(k6 支持 `--thresholds`,P95 超标即失败),防止性能劣化被合入
- **线上持续监测**:对核心接口做拨测(1 次/分钟),P95 超阈值告警
- **定期容量压测**:大版本发布前完整跑一轮阶梯压测,与上一份报告对比

## 附:本目录脚本说明

### 网页版测试平台(推荐)

```bash
cd api-perf-test
./run.sh          # 默认 8080 端口,或 ./run.sh 9090
```

浏览器打开 `http://127.0.0.1:8080`,包含三个面板(对应下方三层测试流程):

| 面板 | 功能 |
|---|---|
| ① 冒烟测试 | 单请求 DNS/TCP/TLS/首字节/总耗时拆解,自动计算服务端处理耗时;支持限速、请求参数(Query)与自定义请求头 |
| ② 采样监测 | 长时间低频采样,实时延迟走势图 + P50~P99 + 慢请求记录表;支持弱网模拟 |
| ③ 压力测试 | 阶梯加压(Java 虚拟线程,支持高并发),实时 QPS/延迟双图、阶段结果表、错误分布 |

**请求头 / 请求参数均为 Key-Value 行式输入**(冒烟、监测、压测一致):每行「勾选框 + Key + Value + 删除」,提交时自动转换为对应格式(请求头 -> `Key: Value`,Query 参数 -> `?k=v&k2=v2` 由服务端拼接)。**勾选框默认选中,取消勾选则该行不携带**(便于临时禁用某个参数对比效果);仅剩一行或仅剩一个接口时删除按钮自动禁用,防止误删。历史记录复用时按 KV 形式回填。

三个面板均支持 **多接口同时测试**(最多 10 个),**每个接口可单独配置**:协议(http/https/ws/wss)、方法(GET/POST/PUT/DELETE)、请求参数、自定义请求头(每行一个 `Key: Value`)。全局 Token 对所有接口生效。

**WebSocket(ws/wss)**:切换协议为 ws/wss 后,自动禁用方法与请求参数,显示大号消息输入框(每次循环发送一次),并实时展示**消息收发记录**(S=发送/R=接收,带精确到毫秒的时间戳)。WS 采样/压测按「发送消息 → 收到回复」的往返耗时计时,自动断开重连。压测时**每个接口都会分配到完整配置的并发数**(如配 100 并发、3 个接口 = 总并发 300)。

**压测记录**:每次压测结束(含手动停止)自动保存配置 + 结果到 `history/` 目录,压测面板底部可查看历史记录详情、一键**复用配置**(回填所有接口配置/阶段/弱网参数后可直接重跑,便于对比优化前后)、删除记录。

网络预设按钮(正常/4G/3G/弱3G)**选中后高亮**,手动修改任意弱网参数会自动取消高亮。

三个面板均支持 **Token 鉴权**(自动 Bearer,或填 `X-Token: xxx` 形式自定义 Header)与**弱网模拟**:

| 预设 | 延迟 | 抖动 | 下行 | 上行 |
|---|---|---|---|---|
| 正常 | - | - | 不限 | 不限 |
| 4G | 60ms | ±20ms | 1500KB/s | 400KB/s |
| 3G | 200ms | ±80ms | 300KB/s | 100KB/s |
| 弱3G | 400ms | ±150ms | 50KB/s | 30KB/s |

弱网模拟为应用层实现(发送前 sleep 模拟 RTT + 按字节比例节流收发),无需 sudo 改系统配置,只影响测试工具发出的请求。注意:开启弱网后耗时包含模拟网络时间,用于评估弱网用户体验;定位服务端本身耗时时请关闭弱网。

技术实现:单文件 `PerfServer.java`(JDK 21+,零依赖,仅绑定 127.0.0.1)+ `index.html`(无前端依赖)。压测在服务端执行,不受浏览器并发数限制。

### 命令行脚本(无需浏览器时的备选)

| 文件 | 用途 |
|---|---|
| `smoke.sh` | 单请求各阶段耗时拆解(冒烟测试) |
| `monitor.sh` | 长时间低频采样,抓间歇性慢请求,生成慢请求日志 |
| `analyze.awk` | 对 monitor 采样数据统计 P50/P90/P95/P99/MAX |
| `k6-load.js` | k6 阶梯压测脚本,含 P95/P99 阈值断言 |
